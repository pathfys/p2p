# 🎁 Gift Parser Bot

Telegram-бот на Python (aiogram 3) для поиска коллекционных подарков (NFT) и их владельцев.
Это обычный бот с inline-кнопками, без Mini App.

## Возможности

| Кнопка | Что делает |
|---|---|
| 🔍 **Быстрый поиск** | Принимает любой текст: название подарка, модели, фона или узора (`Plush Pepe`, `Onyx Black`), несколько слов сразу, ссылку `t.me/nft/PlushPepe-1` (бот запрашивает подарок с сайта в момент поиска) или `@username` владельца |
| 🎛 **По фильтрам** | Подарок (коллекция), 🎨 фон, 🧩 модель, 🔣 узор + режим. Варианты берутся из базы, выбор кнопками с пагинацией |
| 🌱 **Лёгкий** | Владельцы с портфелем до `TIER_MEDIUM_TON` (30 TON) |
| ⚖️ **Средний** | Портфель от `TIER_MEDIUM_TON` до `TIER_RICH_TON` (30–300 TON) |
| 💎 **Rich** | Портфель от `TIER_RICH_TON` (300 TON), самые богатые идут первыми |
| 🎲 **Все подарки** | Случайные люди с абсолютно разными подарками из всей базы, без учёта фильтров и уровня. Бот старается брать подарки из разных коллекций |
| 📊 **Статистика** | Размер базы и распределение владельцев по режимам |

Выбранный режим (🌱/⚖️/💎/🎲) запоминается для каждого пользователя и применяется и к быстрому поиску,
и к поиску по фильтрам.

### Выдача людей: страницы и «Повторить»

Результат поиска и режима «Все подарки» — **люди** (Telegram-аккаунты с @username), у каждого показан
подходящий подарок. Один «парсинг» подбирает `PEOPLE_PER_PAGE × PEOPLE_PAGES` человек (по умолчанию 20):

- **стр. 1** — 10 человек и кнопка **➡️ След. страница**;
- **стр. 2** — ещё 10 человек, кнопки **⬅️ Назад** и ниже **🔁 Повторить**;
- **🔁 Повторить** запускает новый парсинг по тому же запросу и выдаёт **новых** людей (уже показанные
  не повторяются; когда подходящие заканчиваются — список начинается заново).

Если `LIVE_CHECK=1` (по умолчанию), перед выдачей каждый человек проверяется живым запросом к его странице
`t.me/nft`: если подарок уже сменил владельца или выведен в блокчейн — человек заменяется следующим кандидатом.
Это только чтение публичной страницы; бот никому не пишет и не рассылает сообщения.

### Обязательная подписка на канал

Если задан `REQUIRED_CHANNEL` (по умолчанию `@fiestagod`), до подписки бот показывает экран с двумя кнопками:
**📢 Подписаться** (ссылка на канал) и **✅ Проверить подписку**. Подписка проверяется через Bot API
`getChatMember`, поэтому **бота нужно добавить в канал администратором** — иначе проверка невозможна, и тогда
бот никого не блокирует, а в `/admin` появляется предупреждение. Администраторы из `ADMIN_IDS` проходят без
проверки, подтверждённая подписка кешируется на 10 минут.

**Приветствие** (`app/texts.py → welcome`):

```
👋 Привет, Имя!

🎁 Gift Parser — бот для поиска коллекционных подарков Telegram (NFT) и их владельцев.

Что я умею:
🔍 Быстрый поиск — пришлите название подарка, ссылку t.me/nft/… или @username
🎛 По фильтрам — подарок, фон, модель и узор
🌱 Лёгкий · ⚖️ Средний · 💎 Rich — уровень владельцев в выдаче
🎲 Все подарки — случайная подборка из всей базы

📦 В базе: 900 подарков · 484 владельцев · 120 коллекций

Выберите действие 👇
```

## Запуск

Нужен Python 3.11+.

```bash
cd gift_parser_bot
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # впишите BOT_TOKEN от @BotFather и свой ADMIN_IDS
python run.py
```

Затем отправьте боту `/admin` и нажмите **▶️ Запустить парсер**. Можно и `PARSER_AUTOSTART=1` в `.env`.
Бот сам скачает список коллекций и floor-цены с Fragment и начнёт заполнять базу с самых дорогих коллекций.

Тесты: `pip install pytest && python -m pytest`.

## Чем обеспечивать парсер (по документации core.telegram.org)

Разбор сделан по [Bot API](https://core.telegram.org/bots/api) (версия 10.3 от 24.08.2026 и [changelog](https://core.telegram.org/bots/api-changelog)),
разделу MTProto [Gifts](https://core.telegram.org/api/gifts) и [Bots FAQ](https://core.telegram.org/bots/faq) (лимиты).
Есть четыре источника данных, бот использует все четыре:

| # | Источник | Что даёт | Что нужно | Ограничения |
|---|---|---|---|---|
| 1 | **Публичные страницы `t.me/nft/<slug>-<n>`** (`app/parsers/nft_page.py`) | Модель, фон, узор с редкостью, тираж, владелец: `@username`, имя или TON-адрес | Ничего | Нужно перебирать номера. Если у владельца нет публичного юзернейма, видно только имя |
| 2 | **Fragment** (`fragment.com/gifts`, `app/parsers/fragment.py`) | Список всех коллекций (сейчас 120) и floor-цена каждой в TON | Ничего | Floor считается по лотам Fragment. Внутренний маркет Telegram (в звёздах) может отличаться, поэтому есть `/floor` для ручной правки |
| 3 | **Bot API `getUserGifts` / `getChatGifts`** (Bot API 9.3+, `app/parsers/botapi.py`) | Все уникальные подарки пользователя или канала (`OwnedGiftUnique` → `UniqueGift`: model/backdrop/symbol, `rarity_per_mille`) и `sender_user` (кто подарил) | Только токен бота | Нужен числовой `user_id`, по @username бот искать не может. Источники id: пользователи бота и отправители подарков, найденные в чужих портфелях, поэтому база растёт как снежный ком |
| 4 | **MTProto (userbot, Telethon)** (`app/parsers/mtproto.py`, необязательно) | `payments.getSavedStarGifts` даёт подарки любого `@username`. Ещё есть `payments.getUniqueStarGift(slug)`, `getResaleStarGifts` (маркет), `getUniqueStarGiftValueInfo` (floor/последняя продажа) | `API_ID` и `API_HASH` с my.telegram.org и аккаунт (`python -m app.login`) | `contacts.resolveUsername` жёстко лимитирован (FLOOD_WAIT), поэтому источник медленный. Используется для живого поиска `@username` и фонового дообогащения богатых владельцев |

Минимальная рабочая конфигурация: **1 + 2 + 3**, то есть только токен бота. MTProto включается, если задать `API_ID`/`API_HASH`.

## Скорость

**Официальные лимиты Telegram** (Bots FAQ) касаются только отправки сообщений: около 30 сообщений/с на бота,
1 сообщение/с в один чат, 20 сообщений/мин в группу. Для методов чтения (`getUserGifts`, `getSavedStarGifts`,
страницы `t.me/nft`) лимиты не опубликованы. Сервер просто отвечает `429 Too Many Requests` с `retry_after`
или `FLOOD_WAIT_X`.

Поэтому у каждого источника свой ограничитель (`app/ratelimit.py`) и четыре пресета (кнопки в `/admin` или `PARSER_SPEED`):

| Источник | slow | normal | fast | auto |
|---|---|---|---|---|
| t.me/nft (req/s) | 2 | 5 | 12 | от 1 до 18 |
| Fragment | 0.5 | 1 | 2 | от 0.25 до 3 |
| Bot API getUserGifts | 5 | 15 | 25 | от 2.5 до 37.5 |
| MTProto | 0.5 | 1 | 3 | от 0.25 до 4.5 |

**auto** (по умолчанию) подбирает скорость сам. Каждые 25 успешных ответов скорость немного растёт, а на каждый
429/FLOOD_WAIT падает вдвое, и парсер выжидает `retry_after`.

**Замеры (04.10.2026):** в режиме auto парсер разогнался до ~12.5 стр/с (6 потоков) без единого 429.
Всего в 120 коллекциях ~11.7 млн NFT:

| Что парсим (`CRAWL_MIN_FLOOR_TON`) | Коллекций | NFT | Время при ~12 стр/с |
|---|---|---|---|
| floor ≥ 1000 TON | 4 | ~5 тыс. | ~7 мин |
| floor ≥ 100 TON | 14 | ~79 тыс. | ~2 ч |
| floor ≥ 50 TON | 24 | ~183 тыс. | ~4 ч |
| floor ≥ 20 TON | 39 | ~547 тыс. | ~13 ч |
| floor ≥ 10 TON | 55 | ~1.2 млн | ~28 ч |
| все (0) | 120 | ~11.7 млн | ~11 суток |

Рекомендации:
- Оставьте `auto`. Если в `/admin` растёт счётчик 429, переключите на `normal`.
- Для режима 💎 Rich достаточно `CRAWL_MIN_FLOOR_TON=20` или `50`: дорогие коллекции парсятся первыми.
- Курсор каждой коллекции сохраняется в БД после каждого пакета (`CHUNK_SIZE`), поэтому после перезапуска
  парсинг продолжается с того же места. Через `RECRAWL_HOURS` коллекции обходятся заново, чтобы обновить владельцев.

### Отклик выдачи людей (2 страницы = 20 человек)

Это не фоновый обход, а ответ на кнопку. Замеры на тестовой базе (6 220 подарков; и синтетическая БД на 1 млн
подарков / 350 тыс. владельцев). Ответ состоит из выборки людей из SQLite + живой проверки `t.me/nft`:

| Что считаем | Время на 20 человек |
|---|---|
| Выборка из базы (режим «Все подарки», случайные люди) | **4–5 мс** |
| Выборка из базы с фильтром (фон/коллекция) | **15–150 мс** |
| Выборка из базы, свободный текст (LIKE по всем полям) | до **~1.1 с** на 1 млн подарков |
| Живая проверка 20 человек на `t.me/nft` (20 запросов, лимитер `live` ~30 req/s) | **~0.7–1.3 с** |
| **Итого отклик на 2 страницы с `LIVE_CHECK=1`** | **≈0.7–1.3 с** |
| **Итого с `LIVE_CHECK=0` (без проверки, прямо из базы)** | **единицы–сотни мс** |

Переход «След. страница» / «Назад» мгновенный (данные уже в памяти, ~1–3 мс) — живая проверка делается один раз
на весь парсинг, а не на каждую страницу. Время живой проверки зависит от пресета скорости и лимита `t.me`:
при `slow` — медленнее, при `fast`/`auto` — ~30 запросов/с. Текстовый поиск — самый дорогой на большой базе;
фильтры по коллекции/фону работают по индексам и быстрые.

## База данных (SQLite, `data/gifts.db`)

- `users`: пользователи бота (режим поиска) и найденные отправители подарков (очередь для `getUserGifts`).
- `collections`: slug, название, тираж, `floor_ton`, курсор парсера.
- `owners`: владелец (`user_id` / `username` / `ton_address`), число NFT, оценка портфеля `value_ton`
  (сумма floor его подарков) и режим `tier` (`light` / `medium` / `rich`). Если один и тот же человек найден
  разными источниками, записи склеиваются.
- `gifts`: каждый NFT с моделью, фоном, узором, редкостью (‰) и владельцем.

Как наполняется база:
1. Фоновый обход `t.me/nft` по всем коллекциям.
2. Каждый новый пользователь, нажавший `/start`, сразу проверяется через `getUserGifts`.
3. Отправители подарков из ответов `getUserGifts` попадают в очередь.
4. С MTProto ещё и портфели владельцев по @username.

## Админ-команды (только для `ADMIN_IDS`)

- `/admin`: статус парсера, запуск и остановка, скорость, синхронизация коллекций и floor.
- `/floor plushpepe 7000`: задать floor вручную (`/floor plushpepe auto` возвращает автообновление).
- `/recrawl plushpepe`: пропарсить коллекцию заново с №1.
- `/parse_user 123456789`: проверить подарки пользователя через Bot API.

## Работает ли парсер на сессиях?

Нет. **Фоновый парсер не использует сессии аккаунтов.** Три основных источника работают без входа в аккаунт:

1. **t.me/nft** — это обычные HTTP-запросы к публичным страницам, как открыть их в браузере. Ни аккаунта,
   ни токена, ни сессии.
2. **Fragment** — так же, публичные страницы `fragment.com/gifts`.
3. **Bot API `getUserGifts`** — работает с токеном самого бота (не аккаунт, не сессия пользователя).

**Сессия (один аккаунт Telegram) нужна только для необязательного 4-го источника — MTProto/Telethon.** Он
включается, лишь если вы сами впишете в `.env` `API_ID` и `API_HASH` и один раз выполните `python -m app.login`
(ввод номера, кода и пароля 2FA — создаётся файл `.session`). По умолчанию MTProto выключен. **Фермы сессий в
проекте нет** — максимум один аккаунт, и только если вы сам его подключите; он нужен, чтобы находить подарки по
`@username` (Bot API так не умеет).

Принцип работы коротко: фоновый парсер перебирает номера подарков на `t.me/nft`, складывает модель/фон/узор/
владельца в SQLite и считает для каждого владельца оценку портфеля (режим light/medium/rich). Когда пользователь
ищет, бот берёт готовых людей из базы и (если `LIVE_CHECK=1`) на лету перепроверяет страницу каждого — всё это
только чтение публичных данных.

## Важно

Бот собирает только то, что Telegram и так показывает публично: страницы `t.me/nft`, профили, Fragment.
Если владелец скрыл подарок или юзернейм, бот его не раскрывает, и никому не пишет и не рассылает сообщения —
это инструмент поиска и аналитики, а не рассылок. Соблюдайте [условия Telegram](https://telegram.org/tos)
и [Bot Developer ToS](https://telegram.org/tos/bot-developers): **не используйте список владельцев для спама,
рассылок, выпрашивания подарков, фишинга или иной нежелательной связи** — это нарушает правила Telegram и может
навредить людям. Если запускаете userbot, учитывайте, что агрессивный парсинг с аккаунта может привести к его
ограничению.
